Agentic Video Eval · 设计说明 · 2026-09-09

把视频评测当成搜索，而不是打分

这份文档说明当前框架为什么这么设计、每个决定背后的证据是什么， 以及哪些结论已经被数据支持、哪些还只是假设。 末尾是需要你定夺的下一步。

01

问题出在哪

常规做法是：均匀抽 8 帧，配一段固定 prompt，让 VLM 给个 1–5 分。 这条路的瓶颈不是「prompt 写得不够好」，而是三个物理限制——每一个都无法靠改写 prompt 绕过。

采样

120 帧里取 8 帧是 6.7% 的盲采样。生成缺陷是瞬态的，集中在运动峰值和转场处。采样没覆盖到的缺陷，写什么 prompt 都不可能被扣分。

解法：自适应搜索

分辨率

占画面 6% 的人脸，在 VLM 的图像预算里被压到约 30px。判断所需的信息物理上不在模型输入里——它不是没注意到，是被要求判断一份不存在的证据。

解法：原生分辨率裁剪

先验

VLM 预训练几乎全是自然、无瑕疵视频。它对「六指手」「骨长随时间变化」「纹理爬行」缺乏先验——不知道该找什么。

解法：外部检测器与几何不变量

这就是「agentic」的意义所在。三种解法各有代价，用哪个、用多深，取决于输入： 静物镜头和舞蹈特写不该走同一条路径、花同样的钱。固定 pipeline 表达不了这件事。

02

一个重要的拆分

评测一段生成视频其实是两个不同的任务，需要完全不同的机器。把它们压成一个 Likert 分数， 正是现有 benchmark 在头部模型上饱和的原因：合规基本都满分了，自洽的缺陷又因为看不见而没被扣分。

 合规 Conformance自洽 Integrity
问什么视频有没有做条件要求的事？不管条件是什么，它做出来的东西立不立得住？
性质对结构化目标的核对在 (x, y, t) 里搜索缺陷
失败样式少了主体、动作顺序反了、运镜不对六根手指、肢体在变长、纹理沸腾、时间跳变
代价可预测、可并行不可预测、必须自适应

缺陷还要再按「需要多少上下文」分一次。22 类缺陷里恰好 11 类单帧可判定 （手部畸形、穿模、结构崩坏、文字错乱），11 类需要序列（闪烁、卡顿、身份漂移、动作不自然）。

这两半要用完全不同的索引：单帧缺陷的最佳检测器就是 VLM 自己扫帧——没有 CV 信号能识别 「这把椅子几何不成立」，而运动补偿残差对一个稳定存在的缺陷完全失明。

03

系统怎么跑

A

条件编译（离线，每个 prompt 一次）

把 prompt 拆成可逐条核对的要求清单。只看输入、不看任何候选视频，编译一次冻结复用—— 这既保证跨模型公平，也是反 gaming 的关键：policy 无法回避一条它没得选的要求。

B

可疑度映射（在线，纯信号，无 VLM）

用信号处理在全部帧上算出一份排序好的「待查清单」。主力信号是运动补偿残差： 用光流把第 t 帧 warp 到 t+1，剩下的就是运动解释不掉的变化。普通的快速运动会被抵消掉， 而帧差法会把所有快速运动都误报。

C

Agentic 裁决（VLM + 工具，有预算）

模型从该 skill 的动作菜单里选下一步看什么，最多若干轮。菜单是策展过的—— 人物 skill 能放大到脸，运镜 skill 不能，两者互不越界。之后每条指控都要经过反证质询。

D

分数合成（确定性，无 VLM）

从不问 VLM 要分数。分数由确认的、定位的、分级的缺陷机械算出。 每一分扣减都指向一个 (帧区间, 框, 类型)，可以被人复核。

04

为什么模型不直接打分

自由的 1–10 分让判官无处立足。实测：14 条 finding 全部填了 0.5 置信度； 420 个 aspect 分数只有 3 个取值。分辨率不是靠细分档位得来的—— 再细分只会让它更往中间挤。

所以判官只判档位，分数由档位推出：

clean10未发现问题
trace8只有逐帧仔细看才能发现，正常观看完全不影响
minor6认真观看时能注意到，但不影响整体观感
major4正常观看一眼可见，明显损害成片质量
severe2毁掉这个镜头，或使视频无法用于其预期用途

而且每一类缺陷都写了自己的四档判据，并且带分界线。 「手部畸形什么算 major」和「闪烁什么算 major」不是一回事，通用刻度说不清任何一个：

hand_malformation · minor(6分)

能明确指出问题——某帧手指数量不对——但只出现在个别帧，或手在画面中较小。 分界：按正常速度播放会不会注意到？会注意到就是 major；只有暂停或放大才发现，就是 minor。

分辨率来自增加判断轴，不是增加档位。每个轴都保持在模型判得准的粒度：

severity 严重度 trace / minor
major / severe 看到它时有多严重
extent 持续范围 flash / brief
recurring / throughout 占了多长时间
salience 显著位置 peripheral
secondary / primary 在不在观众看的地方

4 × 4 × 3 = 48 种组合，单条 finding 可产生 44 个不同分数。 同样是「major 手部畸形」：一闪而过且在背景里 = 7.33， 全程持续且在主体上 = 4.60。

salience 这个轴补上了严重度根本表达不了的东西——主体特写上的手部畸形， 和背景路人身上同样的畸形，不是一回事。

05

三个反直觉的设计，和它们的证据

证据必须能回答被问的问题

判官 85% 的 finding 挤在 major 一档。原因不是档位文字写得差—— 是 severity 的分界写的是「正常尺寸下会不会注意到」， 而搜索阶段返回的全是放大裁剪。四个轴里三个答不了，答不了的问题就退回中间偏高的那档。

修法：证据包必须配对给出全图原尺寸（判严重度和位置）+ 放大图（判存在性）+ 全片采样（判范围）。跨 8 条不同视频实测后，severity 从 85% 挤一档变成 minor 4 / major 4。

反证的举证责任必须放在「替代解释」身上

第一次真实运行：表面全 10.00，实际是 10 条指控全被撤回。 撤回理由全是同一个形状——提出一个替代解释就完事：「覆盖着泥浆」「快速运动的模糊」。

每个解释单独看都成立。问题在于我写的是「存疑一律 retract」， 而对任何视觉现象，足够聪明的模型总能编出无罪解释。这等于把标准设成「必须排除一切其他可能」。

更糟的是它形成闭环：为降低假阳性建的两个机制（免罚清单、易混淆项）， 被反证方当成了万能免罪符。

修法：反证方必须验证自己的解释——说是运动模糊，就得在慢速帧找到该部位清晰的证据。 给不出支持证据的，代码层强制不予撤回。撤回率从 100% 降到 0–43%。

沉默不等于无罪

三条视频里，46 个 aspect 拿满分，只有 7 个有扣分——而那 46 个从未被判定过， 只是恰好没有 finding 落上去。被问「列出你确认的问题」时，判官只报最显眼的一两个。

任何打分公式都无法在它没拿到的输入上做出区分。

修法：判官必须对 skill 覆盖的每一个 aspect 表态。覆盖了却没表态的， 报「未检查」而不是给满分——否则少跑一个 skill 反而会抬高总分。

06

验证到哪一步了

这一节是这份文档最重要的部分。已验证指有实测数字支撑，未验证指目前只是设计假设。

主张状态证据
448px 裁剪能让 VLM 看出手指缺陷 已验证 三个模型都报出了空间定位的具体畸形
agent loop 会选合理动作、不崩溃 已验证 8 skill 全跑通，动作序列符合级联设计
档位 + 三轴能产生足够分辨率 已验证 44 / 48 个不同分数
逐项表态能拉开模型差距 已验证 合成对照 7.45 / 6.70 / 5.45
多相位共识能滤掉采样噪声 部分 丢弃率 29–44%，丢的是单相位噪声
可疑度图优于均匀采样 部分 短瞬态缺陷上 hit@10 0.50 vs uniform@8 0.31
改动后的信噪比确实提高了 未验证 实验进行中
分数与人类偏好一致 未验证 MQ benchmark 跑批中（100 对）

结论在换判官后仍成立 未验证 只在 gemma-4-31b 上跑过

一个必须记住的负面结果。仅仅把采样相位平移几帧——覆盖同一段视频、同样时长—— 所有有信号的 aspect 信噪比都 < 1（0.20–0.87），总分排序三次跑出三种。

这否定了两个诱人的说法：「人手结构分得开模型」是采样运气； 「扩样本就能做收拢」也不成立，因为这类噪声不随样本量平均。 多相位共识就是针对它做的，但它是否真的把信噪比提上去了，还没测出来。

07

已知的坑

静默失败是这套系统最危险的失败模式。已经抓到过三个，共同点是：不报错、不崩溃、 日志里不留痕，只让结果悄悄变好看——反证举证责任反了导致满分， 编译器漏掉运镜要求，置信度解析失败吞掉整条 finding。 对评测系统而言，偏向乐观的静默失败会让所有模型看起来都不错，正好是要避免的天花板。

现在的护栏一律是「宁可吵闹，不要安静」：撤回率越界标记不可信、兜底补要求并记录、 宽松解析而非丢弃。

指控方与反证方是同一个模型

等于让它自己推翻自己。跨模型反证应该更强，但需要第二个 endpoint 才能验证。

长 prompt 中段的指令会被稀释

同一条约束放在规则块第 7 条时 14/14 失效，挪到输出块正上方立刻生效。 必须始终成立的约束要么放在模型正在写那个字段的位置，要么用代码兜底。

格点重合导致同分

判到同一个类别组合就必然同分。这是分类式判定的固有代价——换来可复现，代价是格点内不可再分。

MQ benchmark 只标了运动

VQ/TA 列全是 invalid，逐视频缺陷标签也几乎没标。所以只能验证运动这一组， 且只能做 pairwise 排序对齐。

08

下一步，需要你定夺

两个实验正在跑，它们的结果会决定选哪条路：信噪比实验（共识值不值 3 倍成本） 和 MQ 100 对（分数能不能预测人的偏好）。下面是几条互斥的方向。

A · 先把人评对齐做扎实

MQ 100 对若显示方向准确率明显高于 50%，就在 dev.csv 上标定 tie 阈值， 扩到全部 998 对报数。这是唯一能说「评得准」的路径。

全量约 5–6 小时 · 只能验证运动一组

B · 先降噪再谈其他

若信噪比实验显示共识没把噪声压下去，那么所有区分度都不可信。 需要先解决「分数取决于恰好看到哪几帧」，否则后面做什么都是在噪声上叠加。

改动在打分与采样层 · 需重跑验证

C · 换更强的模型再评估

目前所有结论都来自 gemma-4-31b。若换强模型后撤回率、分档分布、 动作选择显著变好，那说明当前瓶颈在判官而非架构，优先级要重排。

需要可用的 API key 或第二个 endpoint

D · 扩样本做 aspect 收拢

29 个 aspect 太多。收拢分析（覆盖率/区分度/稳定性/撤回率/冗余度） 已经写好并在合成数据上验过，但必须等信噪比确认后再跑，否则会把噪声当成结论。

依赖 B 先完成

我的建议是 B → A。信噪比是其他一切的前提：如果分数主要由采样运气决定， 那么人评对齐做出来的相关性也是运气的相关性。但如果实验显示共识已经把噪声压住， 那就直接走 A，因为人评对齐是唯一能回答「这套东西到底准不准」的东西。

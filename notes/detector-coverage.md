# 数值层的覆盖边界 —— 2026-09-12

对 8 种合成注入缺陷,每种都在**注入版和它自己的干净原版**上测,因为召回单独不说明问题
(卡顿那轮 85% 检出配 65% 误报)。

## 能做的:全画面时间类(信号峰值,5% 误报下,n=32)

```
frame_repeat   freeze  100% 检出 · 100% 定位
frame_drop     freeze  100% 检出 ·  97% 定位
luma_pulse     crawl    94% 检出 ·  97% 定位
```

## 做不了的:局部空间类(带 bbox 的五种)

信号峰值全部压在 6% 噪声地板上——局部缺陷赢不了全局最大值。
换成 loci 提取(为局部结构而设计的统计量),三种归一化的权衡:

```
归一化              top-3 召回   干净片段提名数   精度上界
exceedance(视频内秩)    31%          10 处        1/3
raw 绝对阈值            15%          24 处(饱和)    —
语料标定 z=3.5           5%           0 处         好但无召回
```

三条路都不成立。信号对这类缺陷本来就不响应:`local_blur` 几乎不改变帧间差分,
`affine_warp` 在数值上就是平滑运动。召回最高的 `patch_swap`/`patch_jump` 正是最突兀的两种。

## 为什么归一化会两难

```
exceedance   视频内的秩变换 → 可比,但无绝对含义,干净片段照样产出 10 处
raw          有绝对含义,但六路信号不可比(softness 的 99 分位 56.3,
             flow_anomaly 只有 0.50,差两个数量级)→ 单一阈值必然饱和
语料标定     各信号在干净语料上各自定标 → 两者兼得,"什么都没有"第一次可表达
```

语料标定是正确的归一化(已加 `compute_maps(calibration=)` 与
`scripts/calibrate_signals.py`),但它救不了本来就不存在的召回。

## 设计后果

**"CV 提名 → VLM 核实"这条链的瓶颈在提名。** 局部缺陷的提名召回上限 31%,
优化核实端的 prompt 不可能补上。实测吻合:逐处判定链 52.8%(随机),
而不做提名、整段视频直接交给 VLM 的路子 65.9%。

```
全画面时间类缺陷   →  数值层(精确、免费、可复现)
局部空间类缺陷     →  VLM 看整段视频(数值层覆盖率≈0)
```

## 分流链路的端到端验证(n=24 注入卡顿)

```
时间类   检出 23/24 = 96% · 定位 23/23 = 100% · 干净版误报 0/24 = 0%
分数     注入版中位 8.4 · 干净版中位 10.0
```

对比:同一模型、同一批视频,让 VLM 自己在时空切片上找卡顿是 0–17%。
差别只在**谁负责找、谁负责判**。

空间类支路**尚未验证**:本轮只注入时间类缺陷,所以两边对空间来说都是干净的。
它对 25% 的真实片段报出问题(注入版 7/24、干净版 6/24),但这可能是真检出
(这些本来就是生成视频)也可能是幻觉,本实验区分不了。需要空间类注入。

## 分屏对比:失败(反方向)

假设:把两段拼成一个上下分屏视频,呈现顺序变成空间位置,可消掉位置偏置。

```
                 acc(无平局)   方向      翻转率    选A率(人评 30%)
顺序呈现(基线)      65.9%     70.2%      23%       40%
分屏同屏           44.6%     60.4%      29%       35%
```

**每个轴都更差,翻转率不降反升。** 最可能是分辨率:每段只剩 436×240,
低于探针测得的 448px 可判读底线。

推论:位置偏置不是"呈现先后"造成的,换成空间排列照样存在,换表示法绕不过去。

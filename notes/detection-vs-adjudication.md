# 检测归数值,判定归 VLM —— 2026-09-11

固定调试集(40 例注入卡顿 + 40 例干净原版,渲染缓存,每例带从渲染像素量出的 band 对比度)
上的对照:

```
              检出      误报      定位
数值检测器     88%       2%      100%
VLM(hybrid)    85%      65%       82%
```

同样的检出率,**误报低 30 倍、定位完美、零 GPU 成本**。

## 结论:分工

```
数值   "0.41–0.48 这段画面完全没变"      精确、免费、可复现
VLM    "此刻本该有动作吗?"               只有它能答
       (静止镜头拍静物 vs 该动的卡住了)
```

**不要让 VLM 去检测和定位时间类缺陷。** 这解释了两个此前孤立的观测:
CV 的 `freeze` 信号是强偏好对上最好的单信号(73.3%),而所有让 VLM 报告卡顿的尝试
都是 0%——不是模型笨,是这件事本来就该让数值做。

## 激发规律:问法决定能不能看见

同一张图、同一个模型,只换问法:

```
"这段视频有没有画面停住?"        12%   判断框架,触发保守先验
"有没有一条比周围暗的带?"        85%   感知框架
再加"暗带意味着卡顿"             33%   领域词汇把它拉回保守
```

**感知与解释必须拆成两次调用,第一次绝不能出现缺陷词汇。**
这与"向它索要程度就得到常数"(margin 99.6% clear / 完整度 96.8% 给 10 /
confidence 14/14 给 0.5)是同一机制的两种表现。

## 方法论:调试集必须带信号门槛

每个案例的 band 对比度是**从模型实际收到的渲染像素上量出来的**,低于阈值标为不可用。
这一天有四次把 prompt 调在一张根本不含信号的图上,每次都看起来像模型的问题:

1. cv2.putText 把中文标注全渲染成 `?`——图的说明书被删了
2. 竖切面板多一次水平翻转——时间轴反向,定位全报成 1−t
3. 固定增益让慢镜头整片发黑——卡顿是黑带,黑带藏在黑底上
4. 脚本硬编码了旧版读图规则——图换了模式,说明书没换

第五次出在验证函数自己:在拼接图上取垂直剖面当时间轴,而拼接图里三块时间向下、
两块时间向右,算出了负对比度(冻结不可能有负对比度)。改成逐面板量之后,
40 例的对比度是 0.64–0.99。

**在说"模型看不见"之前,先用数值确认图里真的有那个东西。**

## 边界

一种缺陷、合成注入、n=40。能否推广到真实缺陷和其他类型未测。
但方法本身(固定调试集 + 渲染像素上的信号门槛 + 数值对照)可直接复用。
